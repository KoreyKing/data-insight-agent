# Data Insight Agent

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

**自部署的 AI 经营分析助手。** 上传一份 CSV / Excel 表格，用一句中文说出你想看什么，它会生成一份**每条结论都能核对**的经营诊断报告——每条结论都附带它依据的 SQL、数据源和运行时间，不是看不清来路的黑盒摘要。

[English →](README.md)

## 为什么用它

多数「和数据聊天」的工具，答案只能凭信任接受，数据跑在别人的服务器上、绑定别人的模型。这个工具不同：

- **产出可核对的报告，而不是聊天回复**：每条结论关联 SQL、数据源与运行时间；报告面向审阅与分享设计，支持导出 PDF。
- **跑在你自己的机器上**：Docker 一行部署，产品方不托管、也看不到你的数据。
- **用你自己的 AI 模型（BYOM）**：任何 OpenAI 兼容接口都可以——OpenAI、DeepSeek、通义千问、OpenRouter、本地 Ollama。模型与数据发送路径由你掌控。
- **行业知识包**：分析建立在行业语义层之上——指标口径、维度定义、分析模板、校验规则，而不是泛泛的提示词。零售经营分析是首个内置行业包。

## 它能做什么

1. 上传一份 CSV 或 `.xlsx`（也可以一键载入内置的零售样例）。
2. 用一句中文说出你想分析什么，比如「本周和上周比，看销售变化和哪些店表现异常」。
3. 系统先把你的目标解析成结构化任务供你确认，再执行有界分析循环：取数、下钻、配图。
4. 你会得到一份带核心指标、关键洞察、图表和下一步建议的报告——每条结论都有「查看依据」入口。
5. 报告与数据源自动留存：历史报告只读可查、可重新打开、可导出 PDF。
6. 把一份报告保存为可复用的分析任务。下一期上传同结构的新文件即可重跑：新报告归入该任务的报告链，并带「对比上期」段落——指标变化由系统计算、不由模型生成，可跳转查看上期报告。结构不一致的文件会在运行前被拦下，并列出缺少 / 多出的字段。
7. 在网页上修改分析所依据的业务口径——指标口径、字段别名、异常阈值——保存前有服务端校验，可一键恢复默认；每份报告都记录生成时使用的口径版本。
8. 每份报告都可以投「有用 / 没用」并补一句话，反馈只保存在你的本地数据库。

## 快速开始

需要 [Docker Desktop](https://www.docker.com/products/docker-desktop/)。

```bash
docker compose up -d
```

- 打开应用：<http://localhost:8000>（前端与 API 同在 8000，单容器）
- 健康检查：<http://localhost:8000/health>

首次启动会从 ghcr 拉取预构建多架构镜像，稍候即可。**不配置模型也能用**：在首页用样例报告入口，即可用内置零售数据跑通完整流程（体验模式，完全离线）。

## 配置你自己的 AI 模型

想分析自己的数据、用自然语言定制分析，需要配置一个 OpenAI 兼容的模型接口。两种方式：

- **界面配置（推荐）**：侧边栏 → 模型配置——选择服务商预设或自定义接口地址，测试连接后保存。密钥仅保存在本地（文件权限 `600`），响应中脱敏展示，不写入日志与报告。
- **通过 `.env` 配置**：

```bash
cp .env.example .env
#   LLM_API_KEY   你的密钥
#   LLM_PROVIDER  服务商预设名（如 deepseek / openai / openrouter），或留空配合下一行
#   LLM_BASE_URL  自定义接口地址（用预设时可不填）
#   LLM_MODEL     模型名
docker compose up -d   # 重启生效
```

## 数据与隐私

- 产品方不托管你的数据。应用在你自己的机器上运行，分析数据只存放在本地（SQLite 文件与上传的临时文件）。
- 当你配置了远程模型接口，分析过程中的数据结构、聚合统计结果与提示文本会**按你选择的模型服务商**的路径发送给该服务商；原始单行明细不会发送。
- 不配置模型时（体验模式）完全本地运行，不向外发送任何数据。

## 环境要求

- Docker Desktop（推荐方式，唯一硬性要求）。
- 本地开发（可选）：Python 3.11+、Node 22.13+、`uv`、`pnpm`（版本由 `frontend/package.json` 的 `packageManager` 锁定）。

## 本地开发（可选）

```bash
make dev            # 同时启动前后端
make backend-dev    # 仅后端
make frontend-dev   # 仅前端
make check          # 跑后端 lint+测试、前端类型检查+lint+测试+构建
make smoke          # 从源码构建 Docker 镜像并启动，检查 /health 与 /
make eval           # 报告质量评估：用你配置的模型在隔离临时库里跑 golden questions
```

`http://localhost:5173` 是 Vite 开发服务器，`/api` 默认代理到 `http://127.0.0.1:8000`；报告生成、样例与上传接口需要后端同时运行。

## 常见问题

- **打开 8000 是空白/连不上**：确认 `docker compose up -d` 已成功、容器在运行（首次会从 ghcr 拉镜像，需稍候）；应用在 `http://localhost:8000`。
- **报告生成报错或提示未配置模型**：未配置模型时仅内置零售样例可跑通（体验模式）；要分析自己的数据，请按上文配置模型。
- **上传文件失败**：当前支持普通的 CSV 和 `.xlsx`（首行表头的二维表）；复杂表头、合并单元格、透视表暂不支持。

## 架构

三层结构：确定性 workflow 外壳（调度、数据连接、报告组装）+ 有界分析内核（固定工具集、硬迭代上限、每条 SQL 过执行控制层校验）+ 行业知识包（承载行业语义）。契约见 [docs/architecture.md](docs/architecture.md)。
